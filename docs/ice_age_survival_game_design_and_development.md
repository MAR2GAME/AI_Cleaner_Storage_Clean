> 文档版本：0.1  
> 项目代号：Icebound Return  
> 游戏名称：《冰原归途》（暂定）  
> 引擎：Godot 4.x 稳定版  
> 目标平台：Android  
> 屏幕方向：横屏  
> 开发规模：个人开发者  
> 文档状态：立项与原型阶段基线

## 1. 文档目的

本文档同时承担游戏设计文档（GDD）和技术开发文档（TDD）的作用，用于：

- 明确正式版范围，防止个人项目无限扩张。
- 统一玩法、剧情、关卡、UI、数值和美术方向。
- 指导 Godot 工程结构与各系统的开发顺序。
- 为 AI 生成 UI、美术概念和开发辅助提供清晰规格。
- 作为版本验收、任务拆分和后续调整的唯一基线。

原型验证后允许修改本文件，但每次修改必须记录在“决策记录”中，避免系统在没有结论的情况下反复推翻。

## 2. 已确认决策

| 项目 | 决策 |
| --- | --- |
| 游戏类型 | 2D 俯视角、单机、生存、狩猎、动作 RPG |
| 核心参考 | 《阿瑞斯病毒》的移动、拖拽瞄准、蓄力攻击和生存循环 |
| 目标平台 | Android |
| 画面方向 | 横屏，参考分辨率 1920×1080，适配 16:9 至 21:9 |
| 操作方式 | 左侧虚拟摇杆移动，右侧拖拽瞄准、蓄力、松手攻击 |
| 世界观 | 以真实史前生态与求生逻辑为主，时间穿越是唯一软科幻设定 |
| 主角目标 | 从现代穿越到冰川时代，在猎杀、战斗和求生中寻找回家的方法 |
| 首发内容 | 单人线性主线，不做营地自由建设、同伴跟随、潜行系统和分支结局 |
| 联网需求 | 核心游戏全程离线；只有购买验证和可选崩溃上报需要网络 |
| 商业模式 | 免费序章 + 一次性买断完整内容；无强制广告、抽卡、体力和数值内购 |
| 正式版长度 | 主线约 4～6 小时，完整探索约 6～8 小时 |
| 开发周期 | 业余开发约 12～18 个月；全职开发约 8～12 个月 |

### 2.1 范围原则

所有新功能必须至少满足以下一项：

1. 强化“冰川环境中的猎杀与求生”。
2. 强化“寻找回家之路”的剧情推进。
3. 明显改善移动端战斗手感或可读性。

不满足上述条件的功能不进入首发版本。

## 3. 产品概述

### 3.1 一句话介绍

一名现代人意外穿越到距今约两万四千年的冰川时代，在严寒、饥饿和史前猛兽的包围中学习古老的生存方式，并沿着异常天象留下的线索寻找返回现代的道路。

### 3.2 玩家体验目标

玩家应持续感受到四件事：

- **危险可判断**：猛兽很危险，但攻击有预兆，死亡主要来自错误判断而非突然袭击。
- **准备有价值**：衣物、食物、火种、武器和路线规划会明显改变探索结果。
- **狩猎有过程**：发现痕迹、追踪、交战和处理猎物共同构成狩猎，而不是普通怪物掉落。
- **归途在推进**：每个区域都必须提供新的时代线索，而不是单纯重复搜集资源。

### 3.3 差异化卖点

1. 体温与天气深度参与战斗和探索，而不是一根独立倒计时。
2. 写实史前动物行为与具有预警、蓄力和距离判断的俯视角战斗。
3. 现代人与史前人类无法直接交流，通过动作、图形和共同狩猎建立信任。
4. 不依赖等级碾压，成长主要来自知识、工具、装备和玩家操作。
5. 一段体量受控、能够完整结束的单机故事。

### 3.4 目标用户

- 喜欢生存、制作、探索和单机剧情的 Android 玩家。
- 喜欢《阿瑞斯病毒》式移动端战斗，但希望体验不同世界观的玩家。
- 能接受适度资源管理，不希望被广告和长期在线系统打断的玩家。

### 3.5 目标体验节奏

- 单次移动端游玩：8～15 分钟。
- 一个小型探索目标：5～10 分钟。
- 一个任务阶段：15～25 分钟。
- 一个章节：45～75 分钟。

## 4. 世界观与叙事

### 4.1 时间和地点

故事发生在距今约两万四千年的末次冰盛期。地点是虚构的北欧亚大陆冰缘谷地，生态与物种参考真实晚更新世资料，但地理结构为玩法服务。

这里存在苔原、针叶林边缘、冰川河谷、石灰岩洞穴和季节性迁徙通道。猛犸象、披毛犀、野牛、狼、洞狮和棕熊在不同区域活动。当地史前人类属于早期现代人类小型群体，不采用“愚昧野人”的刻板形象。

### 4.2 唯一软科幻设定

现代冰川下存在富含石英和磁性矿物的断裂洞穴。在强烈太阳活动、极光和局部地质放电同时发生时，主角经历无法解释的时间位移。

游戏不宣称该现象符合现实科学，只把它作为故事入口。除时间位移外，不出现魔法、超能力、幻想生物或高科技史前文明。

### 4.3 主角

暂定姓名：**林越**。

- 年龄：28 岁。
- 身份：现代户外装备维修师，具备基础攀登、急救和野外露营经验。
- 能力边界：知道基础求生原理，但不会凭空制造现代工业品，也不熟悉史前植物和动物习性。
- 初始弱点：过度依赖现代工具，对长期饥饿、严寒和真实猎杀缺乏准备。
- 人物成长：从“只想立即离开”转变为理解这片土地与帮助过自己的人，同时始终没有放弃回家。

主角采用固定人物形象，首发版不做捏脸和性别选择，以降低立绘、动画、配音和装备适配成本。

### 4.4 史前群体

主角遇到一个正准备跟随兽群迁徙的小型群体，暂称“河谷族”。他们掌握石器加工、制革、保存食物、路径记忆和协作狩猎，知识体系与现代人不同但同样成熟。

双方最初无法进行语言交流。剧情使用以下方式表达：

- 手势和身体动作。
- 在地面或兽皮上的简单图形。
- 展示物品、方向和数量。
- 少量逐渐被主角理解的固定词语。
- 环境演出和任务行为。

不制作完整的虚构语言系统，也不把语言理解做成需要反复刷取的数值。

### 4.5 故事主线

#### 序章：白色断层

主角在现代冰川洞穴中遭遇坍塌和异常极光，醒来后发现通讯、定位和日期全部失效。现代装备只能维持很短时间。玩家完成移动、搜集、点火和第一次防卫教学，并发现冰层中的现代装备不见了，周围却存在巨型动物足迹。

#### 第一章：第一簇火

主角寻找庇护所，靠石片、干草和剩余点火器建立临时火堆。玩家遭遇狼群并第一次处理猎物。章节结尾，主角远远看到史前猎人带走一头猎物，确认自己并非身处无人荒野。

#### 第二章：河谷的人

主角与河谷族发生接触，因误会短暂冲突，随后通过归还工具和帮助驱赶野兽得到临时容身处。玩家学习骨器、制革和保存肉类。主角发现族中一块黑色磁性石片会使已经损坏的电子表短暂出现异常。

#### 第三章：兽群之路

河谷食物不足，需要追随迁徙兽群穿过风口。玩家调查足迹、准备诱导路线并参与一场协作狩猎。NPC 只出现在固定演出和战斗阶段，不形成同伴系统。途中发现与主角穿越洞穴相似的矿脉和壁画天象记录。

#### 第四章：长夜裂谷

主角前往北方裂谷寻找异常源。寒潮迫使玩家依靠更完整的保温装备和固定补给点前进。一个敌对的小型流亡者群体控制了唯一避风洞穴，形成人类战斗章节。冲突原因是生存资源，而不是善恶阵营。

#### 第五章：极光归途

河谷族开始迁徙，主角必须在下一次极光前抵达冰下裂隙。最终狩猎是一头受伤且被困境激怒的洞熊，战斗强调场地、火源和攻击时机。主角启动同类自然现象，在与河谷族告别后回到现代。

结尾中，现代时间只过去很短，但主角带回的石制挂坠仍然存在。故事完整结束，不设置“其实没有回来”的悬念，也不以续作为由截断结局。

### 4.6 叙事原则

- 过场尽量控制在 15～45 秒，可随时跳过并在日志中回看摘要。
- 任务目标必须能够通过地图、图标和环境演出理解。
- 不用长篇文字代替关键动作。
- 不把主角写成凭现代知识征服史前人的“救世主”。
- 动物不是邪恶怪物，其攻击源于领地、饥饿、护幼或受伤。

## 5. 核心玩法循环

### 5.1 长循环

```text
推进主线并解锁区域
        ↓
获得新的知识、工具或保温装备
        ↓
进入更寒冷、更危险的区域
        ↓
追踪猎物、战斗、采集和处理资源
        ↓
返回固定营地补给、制作和保存进度
        ↓
准备下一次远行
```

### 5.2 单次探索循环

```text
在地图选择目标
→ 检查体温条件、食物、药品和武器耐久
→ 离开营地
→ 采集或发现动物痕迹
→ 判断继续深入还是提前返回
→ 战斗或避开危险
→ 携带关键资源回营地
→ 制作、修理并推进任务
```

### 5.3 战斗循环

```text
观察敌人动作
→ 移动到合适距离
→ 拖拽右侧攻击区瞄准并蓄力
→ 根据敌人前摇决定释放、取消或闪身
→ 命中后重新拉开距离
→ 管理耐力、伤势和环境位置
```

### 5.4 核心取舍

每次探索至少要让玩家做出一项实际取舍：

- 多带食物还是多留背包空间给猎物材料。
- 使用耐久较低的高级武器还是保留到关键战斗。
- 穿更保暖但降低移动速度的衣物，还是轻装行动。
- 在天气恶化前返回，还是冒险完成当前目标。
- 点燃珍贵火种保命，还是继续寻找固定避风点。

## 6. 操作与战斗系统

### 6.1 基础触控布局

| 区域 | 操作 | 行为 |
| --- | --- | --- |
| 左下虚拟摇杆 | 拖动 | 八方向连续移动 |
| 右下攻击盘 | 拖动 | 指定攻击方向并进入蓄力 |
| 右下攻击盘 | 松开 | 按当前蓄力阶段发动攻击 |
| 右下攻击盘 | 拖回中心 | 取消攻击，返还未消耗耐力 |
| 闪身按钮 | 点击 | 朝移动方向快速闪身 |
| 交互按钮 | 点击 | 采集、处理、开门、对话或调查 |
| 快捷物品 | 点击 | 使用当前食物、药物或投掷物 |
| 武器切换 | 点击 | 在两个已装备武器之间切换 |
| 菜单按钮 | 点击 | 暂停并打开系统菜单 |

移动、蓄力和调整瞄准可以同时进行，但蓄力时移动速度降低。所有关键按钮允许玩家在设置中调整位置、尺寸和透明度。

### 6.2 攻击规则

- 攻击由方向、有效距离、蓄力、武器类型和目标状态共同决定。
- 瞄准时显示简洁的方向线与有效距离，不显示覆盖半屏的巨大扇形。
- 敌人进入有效攻击范围时轮廓轻微变化，确保小屏幕可判断命中。
- 松手后才扣除耐力与耐久；取消瞄准不消耗资源。
- 普通命中产生短暂停顿和方向反馈，但不使用夸张击飞。
- 部分武器可打断敌人，必须由蓄力阶段和敌人韧性共同判定。

### 6.3 蓄力阶段初始值

以下数值仅用于第一轮原型，不作为最终平衡：

| 阶段 | 蓄力时间 | 伤害倍率 | 耐力倍率 | 用途 |
| --- | ---: | ---: | ---: | --- |
| 快速攻击 | 0～0.35 秒 | 0.70 | 0.65 | 补刀、紧急反击 |
| 标准攻击 | 0.35～0.9 秒 | 1.00 | 1.00 | 常规输出 |
| 完全蓄力 | 0.9～1.5 秒 | 1.45 | 1.30 | 打断、破防、狩猎开局 |

蓄力达到下一阶段时使用音效、武器轻微闪光和短震动提示。不得只依赖颜色，方便色觉异常玩家使用。

### 6.4 闪身

- 闪身距离短，主要用于脱离攻击范围，不表现为连续翻滚。
- 消耗固定耐力，耐力不足时按钮置灰。
- 只提供极短的受击宽限，不允许无脑连续穿过敌人。
- 冰面、深雪和负重状态会影响距离与恢复时间。
- 闪身后有短暂输入缓冲，使玩家可以提前拖拽下一次攻击。

### 6.5 受击与伤害

伤害类型保持精简：

- 切割：石刃、利爪，较容易造成流血。
- 冲击：棍棒、冲撞，较容易削减耐力和造成硬直。
- 穿刺：长矛、角、箭，伤害高但依赖方向和距离。
- 寒冷：不直接作为普通武器伤害，而是推动失温状态。

基础伤害计算建议：

```text
最终伤害 = 武器基础伤害
         × 蓄力倍率
         × 命中部位倍率
         × 武器状态倍率
         × 难度修正
         - 目标防护值
```

计算结果设最小伤害下限，避免低伤害攻击完全无反馈。原型阶段不加入暴击率，弱点命中直接承担高收益作用。

### 6.6 武器类别

| 武器 | 定位 | 优点 | 缺点 |
| --- | --- | --- | --- |
| 石片刀 | 工具兼近战 | 快速、处理尸体必需 | 距离短、正面战斗风险高 |
| 石斧 | 重型近战 | 冲击高、可破坏障碍 | 蓄力慢、消耗耐力高 |
| 木矛 | 主力近战 | 距离长、穿刺稳定 | 转向较慢、耐久一般 |
| 投矛 | 有限远程 | 开战伤害高、可回收 | 携带数量少、落点需要寻找 |
| 投石索 | 轻型远程 | 弹药易得、可引诱动物 | 伤害较低、完全蓄力较慢 |
| 骨角矛 | 后期主力 | 伤害、距离和耐久均衡 | 制作材料稀有 |

首个可玩原型只实现木矛与石斧。远程武器在近战手感通过后再加入。

### 6.7 武器耐久

- 每次有效命中消耗耐久，空挥不消耗或只消耗极少耐久。
- 耐久降至 25% 以下时降低少量伤害，并出现明确 UI 提示。
- 耐久为零时武器变为“损坏”，不永久消失，可在营地修复。
- 修理成本低于重做成本，减少玩家因使用高级武器而产生的囤积心理。

### 6.8 敌人攻击可读性

每种危险攻击必须拥有：

1. 独特起手动作。
2. 可识别声音。
3. 足够玩家做出一次反应的前摇时间。
4. 与动作一致的伤害判定范围。
5. 攻击结束后的明确恢复窗口。

普通难度不使用地面红圈作为主要预警，优先依靠动物动作。无障碍设置可以开启高对比危险轮廓。

## 7. 生存系统

### 7.1 玩家状态

首发版只保留五个核心状态，避免做成仪表盘模拟器：

| 状态 | 主要变化 | 归零或恶化后果 |
| --- | --- | --- |
| 生命 | 受到攻击、流血 | 死亡 |
| 耐力 | 攻击、闪身、短时冲刺 | 暂时无法进行高消耗动作 |
| 饱食 | 随时间缓慢下降 | 耐力恢复降低，随后缓慢损失生命 |
| 体温 | 天气、区域、湿度、衣物、火源共同影响 | 动作迟缓、视野缩小、持续失血 |
| 伤势 | 流血、冻伤 | 产生针对性负面效果 |

口渴、睡眠、精神值、疾病和复杂身体部位伤害不进入首发版。

### 7.2 体温机制

体温是本作最重要的生存系统。内部使用连续数值，界面只显示四段状态：

| 状态 | 表现 | 效果 |
| --- | --- | --- |
| 温暖 | 呼吸平稳 | 无惩罚 |
| 变冷 | 呼吸可见、角色抱臂 | 耐力恢复略降 |
| 寒冷 | 屏幕边缘结霜、动作变沉 | 蓄力速度和移动速度下降 |
| 危险失温 | 心跳、视野收缩 | 持续损失生命，无法快速移动 |

体温变化参考：

```text
体温变化速率 = 区域基础寒冷
             + 当前天气
             + 风力暴露
             + 潮湿惩罚
             - 衣物保暖
             - 火源或洞穴加成
             - 进食产生的短时加成
```

设计要求：

- 新玩家首次离开火堆后至少有 4～6 分钟做出反应。
- 体温下降必须提前通过声音、角色动作和 HUD 呈现。
- 站在避风岩后、进入洞穴或靠近火源都应立即改变趋势。
- 落水会产生“潮湿”，显著提高失温速度；靠火可以快速烘干。
- 体温系统不在营地中持续惩罚玩家，整理背包时自动视为安全。

### 7.3 饱食

- 饱食下降速度以 20～30 分钟需要正常进食一次为基准。
- 奔跑和寒冷会略微增加消耗，但不需要精确计算卡路里。
- 生肉可以紧急食用，但有较高负面效果概率；烤熟后收益稳定。
- 高脂食物提供短时抗寒加成，形成符合题材的食物选择。
- 在菜单和剧情演出期间暂停消耗。

### 7.4 伤势

首发版只有两种持续伤势：

- **流血**：持续损失生命，用纤维绷带处理；完全处理需要在安全状态停留短时间。
- **冻伤**：降低移动和蓄力速度，只能在火源旁逐步恢复，严重冻伤需要使用油脂药膏。

普通受击不会频繁附加伤势。伤势用于放大重大失误，而不是每场战斗后的固定税。

### 7.5 火源

火源用途：

- 恢复体温和烘干潮湿状态。
- 烹饪食物。
- 制作部分工具和药物。
- 在一定距离内威慑谨慎型动物。
- 作为固定营地的保存点。

玩家可以携带一次性临时火种，在允许区域建立小型临时火堆。临时火堆不能升级、移动或扩建，不构成营地建设系统；离开区域较长时间后熄灭。

### 7.6 昼夜与天气

- 一个完整昼夜约 24 分钟，白昼 17 分钟、夜晚 7 分钟。
- 玩家可在固定营地休息到清晨，避免被迫进行夜间探索。
- 天气采用关卡预设与有限随机组合：晴冷、降雪、强风、暴雪。
- 主线关键天气由剧情控制，普通探索天气必须提前预报。
- 天气影响视野、体温和部分动物行为，不改变掉落概率。

## 8. 狩猎、敌人与生态

### 8.1 狩猎流程

完整狩猎由四步组成：

1. 发现足迹、毛发、粪便、叫声或受损植物。
2. 沿有限数量的线索节点确定大致方向。
3. 在有利地形进行战斗或设置一次性诱饵。
4. 使用石片刀处理猎物，在耗时和风险之间取舍。

首发版不加入蹲伏、视野锥和潜行击杀。动物仍有听觉与警戒距离，但玩家通过绕路和停步控制接敌，而不是进入独立潜行模式。

### 8.2 尸体处理

- 动物死亡后不会直接爆出整齐道具。
- 玩家靠近尸体选择处理部位：肉、皮、骨、筋腱或脂肪。
- 每次处理消耗少量时间和工具耐久，并提高附近食肉动物出现的风险。
- 背包容量不足时必须放弃部分材料。
- 任务动物提供独立关键材料，不被随机数阻断。

### 8.3 敌人状态机

```text
休息/巡游
   ↓
听见或看见异常
   ↓
警戒观察
   ├─ 威胁消失 → 返回巡游
   ├─ 可以驱离 → 威吓
   └─ 确认攻击 → 追击
                    ↓
                  攻击
                    ↓
          受伤逃跑 / 再次追击 / 死亡
```

动物根据领地、饥饿、受伤和群体状态使用不同分支，但技术上共享同一个有限状态机框架。

### 8.4 首发动物清单

| 动物 | 行为特点 | 主要资源 | 战斗角色 |
| --- | --- | --- | --- |
| 雪兔 | 发现玩家后逃跑 | 少量肉、皮 | 教学猎物 |
| 驯鹿 | 保持距离、受伤后逃跑 | 肉、皮、筋腱、角 | 中型追猎目标 |
| 野牛 | 警戒后直线冲撞 | 大量肉、厚皮、骨 | 冲撞型精英 |
| 狼 | 试探、绕侧、低血量撤退 | 皮、牙、肉 | 群体压力 |
| 洞鬣狗 | 争夺尸体、短距离猛攻 | 皮、牙 | 尸体处理威胁 |
| 洞狮 | 隐蔽等待、长距离扑击 | 稀有皮、牙 | 章节精英 |
| 棕熊/洞熊 | 领地威吓、重击和扑压 | 厚皮、脂肪、爪 | 最终狩猎 |
| 猛犸象 | 群体行动、护幼、驱赶 | 剧情限定资源 | 协作狩猎演出 |

披毛犀作为后续内容候选，首发阶段只做远景生态演出，避免增加一套大型敌人骨骼与行为。

### 8.5 人类敌人

人类敌人只在第四章集中出现，复用玩家的武器和战斗规则：

- 持矛者：控制距离，蓄力突刺。
- 投石者：保持距离，迫使玩家移动。
- 首领：在两种武器间切换，不拥有超自然技能。

人类不会像动物一样被处理尸体，也不掉落大量人体材料。战后获得的是工具、食物和任务物品。

### 8.6 Boss 原则

- Boss 是特殊狩猎，不是血量异常膨胀的普通动物。
- 每场 Boss 至少有一个场地机制，如火源、狭窄通道、落冰或高低差。
- Boss 动作不超过 5 种基础攻击，阶段变化以组合和节奏为主。
- 玩家准备正确时，Boss 战目标时长为 3～6 分钟。
- 不出现无理由复活、元素法术和连续全屏攻击。

## 9. 物品、背包与制作

### 9.1 背包

- 使用格子背包，不叠加重量系统。
- 初始 16 格，通过剧情制作皮袋后提升到 24 格，正式版上限 32 格。
- 同类资源可堆叠；武器、衣物和大型任务物品单独占格。
- 装备栏不占普通背包格。
- 营地拥有无限容量的分类储物区，减少无意义整理。
- 拾取时支持长按查看用途，背包满时直接显示可替换物品。

### 9.2 装备栏

- 主武器。
- 副武器。
- 外层衣物。
- 足部装备。
- 工具。
- 快捷消耗品。

不加入头、胸、手、腰、腿等大量独立装备位。

### 9.3 资源类别

| 类别 | 示例 | 主要用途 |
| --- | --- | --- |
| 石材 | 燧石、普通石块、磁性黑石 | 武器、工具、剧情 |
| 木材 | 枯枝、硬木杆、树皮 | 火源、矛杆、绑带 |
| 植物 | 干草、纤维、苦味草、浆果 | 点火、绳索、药物、食物 |
| 动物材料 | 生肉、脂肪、皮、骨、角、筋腱 | 食物、衣物、武器 |
| 现代遗留物 | 打火机、急救布、金属扣、损坏电子表 | 序章资源、剧情线索 |

### 9.4 制作层级

| 层级 | 场所 | 示例 |
| --- | --- | --- |
| 徒手制作 | 任意安全位置 | 石片、纤维绳、简单绷带 |
| 火边制作 | 火源旁 | 熟肉、油脂药膏、硬化木矛 |
| 营地制作 | 固定营地 | 皮衣、骨角矛、容量升级 |

### 9.5 首发配方规模

目标总量控制在 24～30 个：

- 6 种武器及升级。
- 4 种衣物和足部装备。
- 4 种药品或包扎用品。
- 5 种食物处理方式。
- 5～8 种工具、火种和任务用品。

每个配方都必须至少在一个具体场景中有清晰用途。不得仅通过更高数值制造大量同质升级。

### 9.6 知识解锁

玩家没有传统角色等级和经验条。配方通过以下方式解锁：

- 主角根据现代知识自动推导基础配方。
- 观察河谷族制作过程。
- 调查遗址或壁画。
- 完成一次特定狩猎。

解锁时同时展示“新知识”和可制作物品，不要求额外消耗技能点。

### 9.7 交换

河谷族使用直接交换，不使用货币：

- 每件可交换物品拥有简单价值等级。
- NPC 只提供少量固定库存，随章节更新。
- 关键剧情物品不能通过随机交换获得。
- 系统重点是补充短缺资源，不发展为经济模拟。

## 10. 地图与关卡

### 10.1 世界结构

采用多个手工制作的中小型区域，通过出口和世界地图连接。不制作无缝开放世界。

```text
现代冰洞（序章）
        ↓
白桦河谷 ── 河谷营地
        ↓
针叶林缘 ── 猎人避风所
        ↓
兽群风口 ── 迁徙营地
        ↓
长夜裂谷 ── 流亡者洞穴
        ↓
极光冰窟（终章）
```

### 10.2 区域规模

- 每个主区域由 3～5 个相连的小场景组成。
- 单个场景正常穿越时间控制在 1～3 分钟。
- 每个场景至少有一个明确地标，避免纯白雪地失去方向感。
- 场景切换点附近不直接生成敌人。
- 返回路线可通过开启近路缩短，但不制作复杂箱庭机关。

### 10.3 区域功能

| 区域 | 视觉特征 | 核心机制 | 主要威胁 |
| --- | --- | --- | --- |
| 现代冰洞 | 蓝冰、现代绳索、应急灯 | 基础教学 | 坍塌、寒冷 |
| 白桦河谷 | 疏林、冻河、浅雪 | 火源、第一次狩猎 | 狼、落水 |
| 针叶林缘 | 深色树林、兽道、岩壁 | 资源准备、接触河谷族 | 狼群、洞狮 |
| 兽群风口 | 开阔苔原、强风、巨型足迹 | 风力、迁徙和协作狩猎 | 野牛、暴雪 |
| 长夜裂谷 | 狭窄峡谷、低光、断裂冰面 | 高级保温、人类战斗 | 流亡者、洞鬣狗 |
| 极光冰窟 | 石英岩壁、极光反射、古老冰层 | 综合验证、最终狩猎 | 洞熊、失温 |

### 10.4 任务规模

正式版目标：

- 1 条完整主线，约 18～24 个任务阶段。
- 6 个短支线，每个 10～20 分钟。
- 8～12 个环境调查点。
- 3 场主要狩猎。
- 1 场人类精英战。
- 1 场最终狩猎。

支线不提供分支结局，主要用于补充人物、生态和制作资源。未完成支线不阻断主线。

### 10.5 资源刷新

- 普通植物和散落石材在 2 个游戏日后有限刷新。
- 普通猎物在离开区域并经过休息后刷新。
- 精英动物、任务资源和地标奖励不刷新。
- 营地附近保留稳定的低价值资源，避免玩家彻底卡死。

## 11. 失败、存档与难度

### 11.1 死亡处理

死亡后回到最近一次固定营地或自动存档点：

- 主线、知识、配方和关键物品不回退。
- 恢复到存档时的普通物品和装备状态。
- 不生成必须跑回远处捡取的尸体包。
- Boss 战前自动建立临时检查点。

目标是保留探索压力，但不通过重复走路惩罚移动端玩家。

### 11.2 存档

- 3 个手动存档槽。
- 1 个持续覆盖的自动存档。
- 固定营地休息、进入新区域、获得关键物品和 Boss 战前自动保存。
- 保存时使用屏幕角落的小图标，不弹出阻断操作的提示框。
- 存档写入采用临时文件后替换，避免中断造成损坏。

### 11.3 难度

首发提供三个预设：

| 难度 | 适用玩家 | 调整内容 |
| --- | --- | --- |
| 故事 | 关注剧情 | 敌人伤害降低、体温下降较慢、攻击提示更明显 |
| 生存 | 默认体验 | 使用设计基准值 |
| 严寒 | 熟悉系统 | 敌人伤害提高、资源略少、状态恶化更快 |

难度只修改数值和提示，不改变敌人数量到影响性能的程度。玩家可在非战斗状态切换难度。

### 11.4 防卡死规则

- 基础石块、树枝和干草永远可以在安全区附近重新获得。
- 剧情武器损坏后仍可使用低效攻击，不会彻底失去推进能力。
- 关键任务物品不能丢弃、交易或用于普通制作。
- 任务目标对象意外离开场景时自动恢复到合法位置。
- 读取存档后执行一次版本迁移和关键状态检查。

## 12. UI/UX 设计规格

### 12.1 UI 视觉方向

关键词：**冰冷、粗粝、清晰、克制、手工痕迹**。

建议色彩体系：

- 冰雪背景：灰白、冷青、低饱和蓝。
- 面板和文字：炭黑、深灰、骨白。
- 交互重点：火焰橙、赭石红。
- 危险状态：高对比暗红。
- 稀有线索：磁性黑石的蓝绿色冷光，只用于时间异常相关内容。

UI 可以带少量石片、骨器、皮绳和炭笔纹理，但轮廓必须简洁。不要把文字直接画进 AI 图片，不使用难以拉伸的大面积装饰边框。

### 12.2 技术画布

- 逻辑参考分辨率：1920×1080。
- 使用横向扩展适配超宽屏，中央内容区保持安全。
- 所有边缘按钮读取 Android 安全区域，避开圆角、打孔和系统手势区。
- 交互按钮最小有效触摸区域建议为参考画布的 96×96 像素。
- HUD 关键文字在 6 英寸设备上仍应清晰，不依靠细小装饰文字。
- UI 图片以透明 PNG 输出；可伸缩面板必须提供九宫格安全区域。

### 12.3 战斗 HUD 布局

```text
┌─────────────────────────────────────────────────────────────┐
│ [头像][生命][体温]       [当前任务简述]       [暂停]       │
│                                                             │
│                                                             │
│ [交互提示]                                      [快捷物品]  │
│                                                [武器切换]   │
│      [移动摇杆]                         [闪身] [攻击拖拽盘] │
└─────────────────────────────────────────────────────────────┘
```

HUD 原则：

- 饱食不常驻为大条，只在变化、偏低或打开状态页时显示。
- 耐力靠近角色或攻击盘显示，停止消耗后逐渐淡出。
- 体温显示当前阶段与变化方向，玩家必须知道正在变暖还是变冷。
- 当前任务只显示一行目标，超出内容在任务页查看。
- 拾取提示不遮挡角色和瞄准线。
- Boss 血条只在主要狩猎中显示，普通动物不显示长条名称框。

### 12.4 主要界面清单

| 界面 | 必需内容 |
| --- | --- |
| 启动与主菜单 | 继续、新游戏、读取、设置、制作人员、退出 |
| 存档选择 | 章节、游玩时间、最后位置、存档日期 |
| 游戏 HUD | 生命、体温、交互、任务、触控操作区 |
| 背包 | 分类、格子、详情、使用、丢弃、装备 |
| 制作 | 分类、配方、材料对比、制作数量、解锁来源 |
| 状态 | 生存状态、伤势、衣物保暖、当前效果 |
| 地图 | 区域轮廓、营地、出口、任务目标、已发现地标 |
| 任务 | 主线、支线、当前阶段、简短历史摘要 |
| 知识 | 动物、植物、工具和时代线索 |
| 交换 | 双方物品、价值差、确认 |
| 暂停 | 继续、保存、设置、返回主菜单 |
| 设置 | 音频、画面、操作、语言、无障碍 |
| 死亡 | 死亡原因、读取最近存档、调整难度 |
| 章节结束 | 关键事件、已解锁知识、下一目标 |

### 12.5 背包交互

- 单击物品：选择并显示详情。
- 双击消耗品：快速使用。
- 长按物品：显示来源和用途，不要求拖拽到很小的目标区。
- 装备和使用按钮固定在详情区，不随描述长度跳动。
- 制作材料不足时直接显示缺少数量和可发现区域。
- 关键物品放在独立标签，不占普通背包空间。

### 12.6 AI 生成 UI 素材清单

AI 只生成没有文字的视觉素材，文字、数字、进度条和交互状态在 Godot 中实现。

第一批必须素材：

- 主面板背景：普通、重要、危险三种。
- 小型提示框背景。
- 物品格：普通、选中、禁用、任务物品四种状态。
- 按钮底图：普通、按下、禁用三种状态。
- 生命、体温、饱食、耐力图标。
- 背包、制作、地图、任务、知识、设置图标。
- 移动摇杆底盘和摇杆帽。
- 攻击拖拽盘、闪身、交互、切换武器图标。
- 地图营地、出口、猎物、资源、任务标记。
- 状态图标：流血、冻伤、潮湿、寒冷、温暖。
- 章节标题装饰、分隔线和小型角花。

第二批素材：

- 物品图标约 50～70 个。
- 武器与衣物详情插图约 12～16 个。
- 动物知识插图约 8 个。
- 章节加载图约 6 张。
- 主角与关键 NPC 半身像约 5～7 张，每人保持固定视角与光线。

### 12.7 AI UI 统一提示词基线

所有 UI 生成任务应复用同一份风格基线，再追加具体物件：

```text
2D mobile survival game UI asset, prehistoric ice age, restrained handmade
materials, charcoal black, bone white, cold desaturated blue, small ochre
accent, rough stone and hide texture used sparingly, clean readable silhouette,
orthographic front view, isolated, transparent background, no text, no letters,
no numbers, no watermark, production game asset, consistent lighting
```

负面约束：

```text
no fantasy runes, no magic glow, no metal frame, no modern plastic, no ornate
RPG decoration, no embedded text, no perspective distortion, no busy background
```

同一批次先生成风格板，通过后锁定模型、提示词、尺寸、色板和随机种子。每类素材先做 3 个样例验证，不直接批量生成全部资源。

### 12.8 AI 图像交付要求

- 保留原始生成图、最终裁切图和提示词记录。
- 图标使用统一方形画布，主体占画布 70%～80%。
- 同类图标使用相同观察角度、描边粗细和光源方向。
- 去除 AI 产生的伪文字、不连续绳索、错误骨骼和多余小物件。
- 面板拆分为底图、边角和纹理层，确认可用于九宫格拉伸。
- 在真机 HUD 中检查，不以电脑大图观感作为最终标准。

### 12.9 无障碍与移动端体验

- 可调整虚拟按键尺寸、位置和透明度。
- 支持瞄准方向灵敏度与拖拽死区调整。
- 提供震动开关，蓄力完成震动强度可调。
- 状态变化同时使用图形、动作和声音，不只使用颜色。
- 提供高对比攻击提示、字幕尺寸和屏幕晃动强度设置。
- 对话和过场支持暂停、跳过与日志摘要。
- 任何需要长按的操作都提供进度反馈。

## 13. 美术与动画

### 13.1 画面风格

建议采用 2D 俯视角手绘风格，人物和动物使用骨骼动画，攻击与受击使用少量关键帧加强力度。

视觉重点：

- 冰雪使用冷灰和低饱和蓝，不把所有场景画成纯白。
- 土地、岩石、枯草、血迹和火焰提供暖色与材质对比。
- 角色轮廓优先于衣物细节，确保手机屏幕上可辨认朝向和动作。
- 动物体型、步态和毛发参考真实资料，不夸张增加角、骨刺或发光部位。
- 时间异常只通过极光、磁石、电子表异常和声音表现。

### 13.2 角色动画最低集合

主角：

- 八方向待机、移动。
- 四或八方向受击、死亡。
- 每种武器的蓄力、攻击和恢复。
- 闪身、采集、处理尸体、点火、进食、包扎。
- 寒冷、严重失温和剧情动作。

普通动物：

- 待机、行走、奔跑、警戒、威吓。
- 2～3 种攻击。
- 受击、低血量、死亡。

大型动物可使用四方向骨骼与运行时翻转，但扑击和侧面动作必须单独检查穿帮。

### 13.3 特效

- 风雪粒子按设备画质档位调整数量。
- 脚印使用对象池和寿命衰减。
- 攻击命中使用短促形变、少量碎屑和音效，不依赖大面积闪光。
- 血液表现可在设置中降低或关闭。
- 火焰使用序列帧或轻量粒子，并提供简单局部光照替代方案。

## 14. 音频设计

### 14.1 音频目标

音频不仅营造氛围，还承担攻击预警、天气变化和动物距离判断。

### 14.2 音频分类

- 环境：风、雪、冰层开裂、河流、树林、洞穴回声。
- 动物：远处叫声、警戒、威吓、攻击、受伤和死亡。
- 战斗：挥动、命中肉体、命中骨骼、石器碰撞、投掷落地。
- 生存：喘息、发抖、饥饿、包扎、点火、烹饪。
- UI：选择、确认、失败、解锁、任务更新。
- 音乐：营地、探索、危险升级、主要狩猎、结尾。

### 14.3 音乐原则

- 探索阶段保持克制，允许环境音承担大部分氛围。
- 使用鼓、骨哨、木石敲击和人声质感时避免声称为真实史前音乐复原。
- 战斗音乐按威胁等级分层，不因单只弱小动物频繁切换。
- 危险结束后平滑退出，不突然回到安静状态。

## 15. Godot 技术方案

### 15.1 引擎选择

- 使用开始开发时的 Godot 4.x 稳定版并锁定小版本。
- 使用 GDScript，避免个人项目同时维护 C# 工具链。
- 2D 项目优先使用 Compatibility 渲染器，以覆盖更多 Android 设备。
- 项目中途不因新特性随意升级引擎；只有明确修复阻断问题时升级。

### 15.2 Android 基线

- 最低系统建议 Android 8.0（API 26）。
- 发布目标 API 按上架时 Google Play 的最新要求设置。
- 首发架构至少包含 ARM64。
- 目标 60 FPS；低画质允许稳定 30 FPS。
- 建议内存峰值控制在 600 MB 以内。
- 初始安装包目标控制在 400 MB 以内，最终上限在内容完成后重新评估。
- 核心玩法在中端设备离线运行，不依赖远程 AI 或服务器逻辑。

### 15.3 工程目录建议

```text
res://
├─ assets/
│  ├─ audio/
│  ├─ fonts/
│  ├─ sprites/
│  ├─ textures/
│  └─ ui/
├─ data/
│  ├─ animals/
│  ├─ items/
│  ├─ quests/
│  ├─ recipes/
│  └─ weapons/
├─ scenes/
│  ├─ actors/
│  ├─ animals/
│  ├─ combat/
│  ├─ levels/
│  ├─ props/
│  └─ ui/
├─ scripts/
│  ├─ autoload/
│  ├─ components/
│  ├─ state_machines/
│  ├─ systems/
│  └─ utilities/
├─ shaders/
├─ localization/
└─ tests/
```

### 15.4 Autoload

只保留真正跨场景的服务：

| 服务 | 职责 |
| --- | --- |
| `GameState` | 当前流程、玩家持久状态、世界标记 |
| `SaveManager` | 存档、读取、版本迁移、自动保存 |
| `SceneLoader` | 异步切换关卡、加载界面、入口信息 |
| `AudioManager` | 音乐层、环境总线、全局音量 |
| `SettingsManager` | 画面、音频、操作和无障碍设置 |
| `EventBus` | 少量真正跨模块事件，不承载局部对象通信 |

不把战斗、背包或任务的所有逻辑塞进单例。局部系统由当前关卡或玩家场景持有。

### 15.5 玩家场景

```text
Player (CharacterBody2D)
├─ VisualRoot
│  ├─ BodySprite/Skeleton
│  ├─ AnimationTree
│  └─ Effects
├─ CollisionShape2D
├─ Hurtbox
├─ InteractionDetector
├─ AimPivot
│  └─ WeaponMount
├─ Components
│  ├─ HealthComponent
│  ├─ StaminaComponent
│  ├─ TemperatureComponent
│  ├─ HungerComponent
│  ├─ InventoryComponent
│  └─ CombatComponent
└─ StateMachine
```

玩家状态建议：`Idle`、`Move`、`Aim`、`Attack`、`Recover`、`Dodge`、`Interact`、`Hurt`、`Dead`。

### 15.6 动物场景

```text
Animal (CharacterBody2D)
├─ VisualRoot
├─ CollisionShape2D
├─ Hurtbox
├─ HitboxRoot
├─ DetectionArea
├─ NavigationAgent2D
├─ Components
│  ├─ HealthComponent
│  ├─ CombatComponent
│  ├─ PerceptionComponent
│  └─ HarvestComponent
└─ StateMachine
   ├─ Idle
   ├─ Roam
   ├─ Alert
   ├─ Threaten
   ├─ Chase
   ├─ Attack
   ├─ Flee
   └─ Dead
```

动物差异尽量来自资源参数、状态组合和少量专属攻击脚本。不要为每个动物复制整套 AI。

### 15.7 数据驱动

静态配置使用自定义 `Resource`：

- `ItemData`：ID、名称键、图标、堆叠、分类、用途。
- `WeaponData`：伤害、距离、蓄力、耐力、耐久、攻击场景。
- `AnimalData`：生命、速度、感知、韧性、行为参数、可处理资源。
- `RecipeData`：输入、数量、场所、输出、解锁条件。
- `QuestData`：步骤、目标类型、文本键、奖励、依赖。
- `WeatherData`：温度、风、能见度、粒子和音频参数。

运行时对象只保存资源引用和变化状态。所有资源都使用稳定字符串 ID，存档不依赖场景节点路径。

### 15.8 输入系统

Godot `InputMap` 同时定义触控与调试输入：

```text
move_left / move_right / move_up / move_down
aim
attack_release
dodge
interact
quick_item
switch_weapon
pause
```

开发阶段必须支持键鼠或手柄模拟触控行为，提高调试效率，但最终平衡以真机触控为准。

虚拟摇杆只输出标准化方向和力度，不直接控制玩家节点。攻击盘输出瞄准向量、拖拽距离和按住时间，由 `CombatComponent` 解释。

### 15.9 命中系统

- 攻击动画在有效帧开启 `Hitbox`，结束后立即关闭。
- 每次攻击拥有唯一攻击 ID，防止单个目标在同一挥击中重复受伤。
- 伤害请求使用结构化数据，包括来源、方向、类型、力度和武器 ID。
- 击退、硬直和受伤由目标组件决定，攻击者不能直接控制目标动画。
- 投射物使用对象池；落地后投矛转换为可拾取对象。

### 15.10 导航与生成

- 地图使用手工导航区域和 `NavigationAgent2D`。
- 动物只在玩家附近启用完整感知与导航，远处使用低频更新。
- 生成点由关卡设计者放置，随机只选择合法点位和有限数量组合。
- 不在玩家视野内突然生成大型动物。
- 大型动物使用简化避障，防止复杂群体寻路拖慢移动端。

### 15.11 任务系统

任务步骤使用明确类型，不解析自然语言：

- 到达区域。
- 调查目标。
- 获得物品。
- 制作物品。
- 击败或驱赶目标。
- 交付物品。
- 观看事件。

任务监听统一游戏事件并更新计数。剧情脚本只控制流程，不直接修改 HUD、背包节点或存档文件。

### 15.12 存档格式

存档使用带版本号的结构化字典，经 `FileAccess` 写入用户目录：

```text
save_version
play_time
current_scene_id
spawn_point_id
player_state
inventory
equipment
quest_states
world_flags
opened_shortcuts
discovered_entries
difficulty
```

写入流程：序列化到临时文件，校验成功后替换主文件，并保留一个上一版本备份。静态配置不写入存档，只记录稳定 ID 和运行时变化。

### 15.13 UI 实现

- HUD、菜单和弹窗分别建立场景，不在一个超大场景中管理全部界面。
- 使用主题资源统一字体、颜色、间距和按钮状态。
- 可伸缩底图使用 `NinePatchRect`。
- 列表使用复用单元，避免一次创建大量复杂控件。
- 安全区、宽屏扩展和触控布局由统一适配层处理。
- UI 逻辑订阅状态变化，不在每帧轮询所有玩家数据。

### 15.14 场景切换

- 大区域之间通过加载界面切换，避免追求无缝世界。
- 加载界面展示章节插图、区域名和一条短提示。
- 进入场景时通过稳定的 `spawn_point_id` 定位，不保存裸坐标作为唯一入口。
- 切换前清理临时投射物、动物仇恨和局部音频。

### 15.15 本地化

- 所有可见文字使用翻译键，不直接写死在场景中。
- 首发最低支持简体中文；英文在内容稳定后加入。
- UI 图片中不烘焙文字。
- 对话文本与程序资源分离，方便修改和校对。

## 16. 性能预算

### 16.1 场景预算建议

| 项目 | 中端设备目标 |
| --- | ---: |
| 同屏完整 AI 敌人 | 8～12 |
| 同屏大型动物 | 2～4 |
| 活跃投射物 | 20 以内 |
| 持续脚印/痕迹 | 80 以内，使用对象池 |
| 主要粒子发射器 | 10～16 |
| 单场景加载时间 | 5 秒以内为目标 |

### 16.2 优化顺序

1. 使用 Godot Profiler 在目标 Android 设备定位瓶颈。
2. 降低远处 AI 更新频率和雪粒子数量。
3. 合并静态图块和减少透明层过度绘制。
4. 压缩大图、限制同时加载的章节资源。
5. 对投射物、脚印、伤害数字和常用特效使用对象池。

不提前为尚未出现的性能问题编写复杂通用框架。

### 16.3 画质档位

- 低：30 FPS、低雪量、关闭局部光照和部分脚印。
- 中：60 FPS 目标、中等雪量、有限局部光照。
- 高：60 FPS 目标、完整粒子、更多环境细节。

首次启动根据简单设备信息选择默认档位，允许玩家随时修改。

## 17. AI 在开发中的使用边界

### 17.1 适合 AI 的工作

- 世界观资料问题清单、任务初稿和物品描述草案。
- GDScript 小模块、编辑器工具和错误分析。
- UI、角色、动物和场景概念图。
- 临时图标、临时配音和音效需求稿。
- 数值表检查、重复内容发现和测试清单整理。

### 17.2 不应直接交给 AI 决定的工作

- 核心战斗手感和数值最终判断。
- 史前文化、动物行为与历史事实的最终准确性。
- 大量相互依赖的游戏架构一次性生成。
- 未经人工检查就直接进入正式版的图片、文本、代码和音频。
- 运行时 NPC 对话或敌人决策。核心游戏不得依赖在线大模型。

### 17.3 AI 资产合规

- 记录模型、版本、提示词、生成日期和后期处理过程。
- 确认所用服务允许商业使用。
- 不要求模型模仿在世艺术家或直接复刻其他游戏的 UI、角色和构图。
- 对关键素材保留人工重绘、分层和修改证据。
- 上架前按商店要求披露生成式 AI 内容。

## 18. 商业与发布方案

### 18.1 商业模式

建议采用：

- 序章和第一章前半段免费，提供 30～45 分钟完整体验。
- 一次性购买解锁余下章节。
- 无强制广告，无复活广告，无资源包和数值道具内购。
- 购买完成后全程离线可玩。

支付系统在垂直切片完成后再接入。早期试玩包直接开放全部测试内容，不让商业系统阻塞玩法验证。

### 18.2 发布渠道顺序

1. 内部 APK：只用于真机操作和性能验证。
2. 小范围测试：邀请目标玩家测试战斗与生存循环。
3. 免费公开试玩版：收集设备兼容和前 30 分钟流失原因。
4. Google Play 正式版：接入购买、隐私声明和崩溃上报。
5. 根据维护能力再考虑其他 Android 渠道。

### 18.3 商店卖点表达

商店页面应直接展示：

- 拖拽蓄力与动物攻击预警。
- 风雪、体温、火源和装备准备。
- 追踪、猎杀和处理史前动物。
- 从现代遗留物到史前工具的视觉反差。
- 明确的单机完整故事与一次性买断。

不要把“AI 制作”作为游戏的第一卖点，玩家购买的是体验，不是生产方式。

## 19. 开发路线图

工期按个人开发者业余投入估算。每阶段完成后再进入下一阶段，不同时铺开所有系统。

### 阶段 0：预制作，2 周

目标：锁定视觉、操作和范围。

- 建立 Godot 工程、Android 导出和真机调试。
- 完成玩家比例、相机距离和参考分辨率验证。
- 制作 UI 风格板、主角轮廓和两种动物概念。
- 建立任务列表、版本命名和资源授权记录。

完成标准：同一测试场景能在目标真机运行，触控区域不被安全区遮挡。

### 阶段 1：战斗原型，4～6 周

目标：证明操作值得继续开发。

- 移动、相机、攻击拖拽盘、蓄力和取消。
- 木矛、石斧两种武器。
- 狼与野牛两种敌人。
- 生命、耐力、伤害、受击、死亡。
- 临时 HUD、音效、震动和基础命中反馈。

完成标准：没有美术包装的情况下，测试者仍愿意连续打 10 分钟，并能理解距离、蓄力和敌人前摇。

### 阶段 2：生存闭环，4～6 周

目标：形成一次完整外出循环。

- 体温、饱食、火源、流血和冻伤。
- 背包、拾取、尸体处理、制作与修理。
- 一个营地和一个 8～12 分钟探索区域。
- 自动存档、死亡恢复和基础设置。

完成标准：玩家可以准备物资、外出狩猎、遭遇天气、带资源返回并制作升级。

### 阶段 3：垂直切片，8～10 周

目标：完成接近正式品质的第一章。

- 序章与白桦河谷。
- 30～45 分钟完整流程。
- 正式主角、狼、驯鹿和环境美术。
- 第一版正式 UI、音频和剧情演出。
- Android 性能与安装包验证。

完成标准：试玩内容能够独立发布并让陌生玩家理解题材、目标和核心循环。

### 阶段 4：内容生产，4～6 个月

目标：完成其余章节和系统内容。

- 河谷族、交换、知识和任务系统。
- 全部区域、普通动物、主要狩猎与人类敌人。
- 全部配方、装备、任务、地图与日志内容。
- 章节插图、角色半身像、环境音和音乐。

完成标准：主线从新游戏到结局可完整通关，允许使用临时素材，但不能存在阻断问题。

### 阶段 5：完善与发布，2～3 个月

目标：稳定、平衡并达到上架要求。

- 真机兼容、性能优化和触控调整。
- 数值、资源分布和难度调整。
- UI 最终替换、本地化、字幕与无障碍。
- 购买流程、隐私政策、商店素材和发布包。
- 修复阻断、存档和购买相关问题。

完成标准：目标设备稳定通关，存档升级可用，购买恢复可验证，无已知阻断问题。

## 21. 验证与验收

按照风险进行必要验证，不建立超出个人项目维护能力的大型测试体系。

### 21.1 每次可玩版本的冒烟检查

- 新游戏能进入首个场景。
- 移动、瞄准、蓄力、取消、攻击和闪身可用。
- 玩家可以受伤、死亡并恢复。
- 拾取、制作、装备和消耗品状态正确。
- 场景切换后背包、任务和状态保持。
- 自动存档可以读取。
- Android 返回键、暂停、切到后台和恢复正常。
- 16:9 与超宽屏的 HUD 不被裁切或重叠。

### 21.2 必须做针对性验证的模块

- 存档版本迁移与损坏恢复。
- 关键任务状态与任务物品防丢失。
- 购买、恢复购买和离线授权。
- 不同帧率下攻击判定、蓄力计时和持续伤害一致性。

其余玩法优先采用测试场景和真机人工验证，避免为快速变化的原型编写大量脆弱测试。

### 21.3 垂直切片玩家测试问题

不要先解释系统，让玩家完成后回答：

1. 你是否知道下一步应该去哪里？
2. 你何时意识到角色正在失温？
3. 你是否理解拖拽、蓄力和松手攻击？
4. 受击时能否说出自己判断错在哪里？
5. 哪一种资源让你感到不必要地重复搜集？
6. 你是否愿意继续寻找回到现代的方法？

同时记录首场战斗死亡次数、第一次返回营地耗时、背包满次数和主动退出位置。

## 22. 主要风险与应对

| 风险 | 表现 | 应对 |
| --- | --- | --- |
| 范围失控 | 不断增加建造、同伴和开放世界 | 以首发范围原则拒绝，不进入当前路线图 |
| 战斗手感不成立 | 拖拽累、误触、瞄准不准 | 在任何大量内容生产前完成真机原型测试 |
| AI 美术不统一 | 角色、图标和面板像不同游戏 | 先锁定风格板、色板、种子和后期规范，再小批量生成 |
| 雪地可读性差 | 角色、足迹和攻击看不清 | 使用深色轮廓、地表层次与可选高对比提示 |
| 生存系统烦琐 | 玩家频繁吃东西和返回火堆 | 降低下降速度，让状态影响选择而非持续打断 |
| 内容生产过慢 | 每种动物都有独立系统 | 共享状态机、骨骼逻辑和数据配置，控制动物总量 |
| 移动端性能不稳 | 风雪、AI 和透明层导致掉帧 | Compatibility 渲染器、画质档位、对象池、近处完整更新 |
| 历史表现失真 | 物种时代、人物文化混乱 | 关键内容查证多个可靠来源，明确虚构地理和软科幻边界 |
| 存档阻断 | 更新后无法继续或关键物品丢失 | 稳定 ID、版本迁移、备份文件和关键状态校验 |
| 商业接入拖延 | 购买系统影响玩法开发 | 垂直切片后才接入，先使用完全离线测试包 |

## 23. 首发不做清单

以下功能明确不进入 1.0：

- 自由营地建设和建筑摆放。
- NPC 同伴跟随与队伍养成。
- 蹲伏、潜行击杀和复杂视野系统。
- 分支主线、多结局和阵营声望。
- 联机、排行榜、云端常驻世界。
- 程序化地图和无限生存模式。
- 坐骑、农业、繁殖和大型驯养系统。
- 复杂疾病、口渴、睡眠和精神状态。
- 随机词条装备、抽卡和稀有度刷取。
- 运行时大语言模型 NPC。
- 完整配音；首发以短语音、呼吸、叫喊和字幕为主。

这些内容只有在正式版完成并证明有用户需求后，才作为独立版本评估。

## 24. 原型成功标准

战斗原型只有同时达到以下标准才进入正式内容制作：

- 80% 的首次试玩者能在 2 分钟内理解移动与拖拽攻击。
- 测试者能通过动作判断狼的扑击和野牛的冲撞。
- 攻击失败主要来自距离、方向或时机，而不是触控误识别。
- 10 分钟战斗过程中没有明显手指疲劳或遮挡关键画面。
- 中端 Android 设备在战斗场景保持稳定目标帧率。
- 木矛与石斧在攻击距离、节奏和风险上有明显区别。

垂直切片只有同时达到以下标准才进入全量生产：

- 陌生玩家可以独立完成 30～45 分钟流程。
- 至少 70% 的测试者愿意继续下一章。
- 玩家能描述体温、火源、狩猎和制作之间的关系。
- 没有存档、场景切换和关键任务阻断。
- UI 在 16:9 和 20:9 真机上可读且不重叠。
- 第一章的美术生产方式可以估算并复制到后续章节。

## 27. 下一步行动

1. 建立一个独立 Godot 原型工程，不在正式资源上投入时间。
2. 以纯色几何图形完成移动、拖拽瞄准、蓄力、取消和木矛攻击。
3. 制作只有三种动作的狼：警戒、扑击、恢复。
4. 在一台目标 Android 真机连续试玩 10 分钟，调整摇杆、攻击盘和相机。
5. 手感通过后加入石斧、耐力和两只狼，再验证群体战斗。
6. 战斗原型通过“原型成功标准”后，开始体温、火源、背包与第一章制作。

本项目当前最重要的交付物不是完整地图或大量 AI 美术，而是一个在 Android 真机上操作准确、攻击可判断、连续游玩不疲劳的战斗原型。
